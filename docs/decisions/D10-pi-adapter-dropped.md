# D10 — `pi` adapter: dropped, `pi` already has a generic MCP client (closes A5)

**Status:** Accepted

**Context:** A5 asked whether to keep a thin TypeScript adapter permanently, or whether `pi` would "eventually" gain a generic MCP client that made it unnecessary. An investigation on 15 Jul 2026 in the maintainer's real environment showed this is no longer hypothetical: `pi` (`@earendil-works/pi-coding-agent@0.80.7`) already runs with the `pi-mcp-adapter@2.6.1` package installed (`~/.pi/agent/settings.json`), has a `~/.pi/agent/mcp.json` with real MCP servers already configured and in use (`chrome-devtools-mcp` and `firecrawl` via a local `command`/`args`, `context7` via a remote `url`), a tool metadata cache (`~/.pi/agent/mcp-cache.json`, with the `servers` key populated — evidence of active use, not just declared config) and a `--mcp-config <value>` flag on `pi`'s own CLI. The `pi-mcp-adapter` package itself is not an MVP — it has an OAuth flow, an elicitation handler, a sampling handler and resource tools, all already implemented.

**Decision:** do not build the thin TypeScript adapter planned for Phase 3. When the M3m0s core exposes an MCP server over stdio (already a P0 item of Phase 1), it is registered directly in `~/.pi/agent/mcp.json` — the same mechanism already used today for `chrome-devtools-mcp`/`firecrawl` (command + args of a local binary/process, which works the same for a Go binary of our own) or `context7` (a remote URL, if we choose to expose it over HTTP instead of stdio). The current `memory-server`/`memory.ts` (a custom `pi` extension, not MCP) are retired once the M3m0s core is validated, with no intermediate adapter step.

**Why:** the premise that justified the adapter ("`pi` does not speak MCP natively") is no longer true — it was true when the original `memory-server` was written, but `pi` has evolved since. Keeping an adapter in this scenario would be redundant work with no gain: one more TypeScript layer to maintain, contradicting [D2](D2-stack-go-core-typescript-only-where-required.md) (minimize TS, minimal footprint).
