# D15 — Phase 7 mechanism (light KG + temporal fact, closes A8)

**Status:** Accepted

**Context:** [A8](A8-light-kg-temporal-fact.md) pointed out that Phase 7 was stuck on a conditional criterion that was never operationalized ("only if Phase 4 shows it is needed", without defining who evaluates or when). The maintainer decided to proceed now (16 Jul 2026) and, on the 3 structured questions that closed the design (`related_to`, `valid_until`, search behavior), answered "do it the way the competitors do" for all three axes — revisiting the original benchmark (the memory-system comparison, 14 Jul 2026).

**What the competitors actually do (re-reading the benchmark):**
- **Zep** (Graphiti): automatic LLM extraction of entities/relations from each ingested datum; facts (edges) carry `valid_at`/`invalid_at` that are updated automatically — when a new fact contradicts an existing one, the old one is invalidated (not deleted); it is not an expiration date guessed at creation.
- **Cognee** (`cognify()`): an ECL pipeline extracts entities/relations via LLM as part of processing, always automatic, writing to a graph (Neo4j/NetworkX).
- **Mem0** (optional graph memory): when enabled, it also extracts entities/relations via LLM from the already-extracted facts.

In all 3 cases it is an automatic LLM decision, never manual user input — which confirms the direction given by the maintainer.

**Decision, in 3 parts (mechanism, no new infra — [D6](D6-getengram-analysis.md) still holds, no Neo4j):**

1. **`related_to` reuses the similarity search that dedup ([D12](D12-llm-fact-extraction.md)) already runs per fact, with no new call.** Today there is only 1 threshold (`DedupSimilarityThreshold = 0.95`, match → merge). Phase 7 adds a second, lower one: `RelatedSimilarityThreshold = 0.65` — the highest-similarity candidate within the same `domain` (the same query that already ran for dedup) that falls in the `[0.65, 0.95)` band becomes a `related_to` candidate. **It needs no LLM for this** — it works even with extraction (Phase 4/[D12](D12-llm-fact-extraction.md)) turned off, it is purely embedding-based. It keeps things "light": it is not a typed entity graph like Zep/Cognee do "for real", it is a link between 2 whole memories.
2. **`valid_until` needs semantic judgment** — similarity alone does not tell "contradicts" apart from "agrees/elaborates" (two contradictory versions of the same fact usually have very close embeddings). When there is a candidate in the band above AND the configured extractor also implements a new `Classifier` interface (`Classify(ctx, newFact, existingFact string) (string, error)`, satisfied by `*extract.Extractor` — the same optional type-assertion pattern that `modelProvider`/`Model()` already uses, [D12](D12-llm-fact-extraction.md)), 1 extra LLM call per fact asks whether the new fact `contradicts`/`related`/`unrelated` to the candidate. `contradicts` → the existing candidate gets `metadata.valid_until = now` (RFC3339), the new fact stays current, and the two become `related_to` each other. Any result other than `contradicts` — including an unavailable classifier (extraction off, or an extractor without `Classify`), a network error/timeout, or an unrecognized response — falls to the safe fallback: `related`, never invalidating anything. The same defensive spirit as [D12](D12-llm-fact-extraction.md) item 5 (never fail the `Add` because of this, never make a low-confidence invalidation).
3. **Search: expired-entry filtering and 1-hop expansion are on by default, with no new parameter to enable them.** `search`/`recent` now (a) exclude by default entries with `metadata.valid_until` in the past, and (b) for each top-K result, if it has `related_to`, include the related entry(ies) in the result (cap +2 per result, without duplicating an ID already present), marked in the `contextBlock` as "↳ related to `<id>`" instead of the normal numbered format. No opt-out flag in this v1 — if it proves noisy in practice, it becomes an opt-out later.

**New fields, no change to `schema.Entry`:** `related_to` (a list of IDs, encoded as a comma-separated string, the same pattern as `keyTags` in chromem) and `valid_until` (RFC3339) live inside `Metadata map[string]string` — the same convention as `file_path`/`heading` (`m3m0s watch`, [D11](D11-watch-mechanism.md)) and `source_content` (Phase 5/[D13](D13-webui-admin-scope.md)): a reserved key inside free metadata, not a first-class field.

**Out of scope for this decision:** compression ([A9](A9-old-memory-compression.md)), memory evaluation ([A10](A10-memory-evaluation.md)), feedback loop ([A11](A11-memory-feedback.md)) — each remains a separate decision, with no dependency relationship to this one.
