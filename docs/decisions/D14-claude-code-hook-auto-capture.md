# D14 — Auto-capture via hook (Claude Code, Phase 8)

**Status:** Accepted

**Context:** [D12](D12-llm-fact-extraction.md) (Phase 4) explicitly left out of scope "the auto-capture hook in `pi` (or any other tool) that would trigger `memory_add` automatically" — the maintainer asked to validate isolated fact extraction first. With Phase 4 validated in real production (real Docker, `pi` inserting memory via MCP, the WebUI showing the result — see the Phase 5 elaboration in [D13](D13-webui-admin-scope.md)), the maintainer asked on 16 Jul 2026 to close this postponed item.

**Decision, in 4 parts (closed with the maintainer before coding, same discipline as [D11](D11-watch-mechanism.md)/[D12](D12-llm-fact-extraction.md)):**
1. **Tool: Claude Code first, not `pi`.** `pi` was the original motivation for the problem (`memory_add` is *pull*, the model has to decide to call it — it does not write on its own), but it has no native hook, only MCP tools. Claude Code already has a native hook system (`PreCompact`/`SessionEnd` among others) — less engineering effort, and it validates the concept before investigating a dedicated mechanism for `pi`.
2. **Trigger: `PreCompact` + `SessionEnd`, treated the same.** `PreCompact` fires right before context is deliberately lost (the critical moment — it even happened in the very session that produced this decision, via `/compact`); `SessionEnd` closes whatever is left since the last capture when the session ends without going through compaction. This first version does not distinguish `trigger` (`manual`/`auto`) nor the `SessionEnd` `reason`.
3. **Registration scope: global, in `~/.claude/settings.json`.** It applies to any Claude Code session in any project — which is what solves the original problem (reducing tokens spent rediscovering context in any work, not just in this repo). Confirmed even though it is a change shared across all of the maintainer's Claude Code projects.
4. **`domain` fallback: `codigo:<basename(cwd)>` always, with no exception for directories outside a git repo.** The same rule as `m3m0s watch` ([D11](D11-watch-mechanism.md)), with no special case for `pessoal:*` — it keeps domain inference predictable and identical across the project's two automatic-capture mechanisms (`watch` observes files, the hook observes sessions).

**Mechanism:** a new subcommand `m3m0s hook claude-code` (Go, same binary, no new dependency): reads the hook's JSON payload from stdin (`session_id`/`transcript_path`/`cwd`/`hook_event_name`), reads the JSONL transcript pointed to by `transcript_path`, extracts only the real text blocks (`type: "text"` inside `user`/`assistant` messages; ignores `tool_use`/`tool_result`/`thinking`) from the lines not yet processed since the last local checkpoint (`~/.m3m0s/hooks/claude-code/<session_id>.json`, in the same spirit as `watch`'s local state, [D11](D11-watch-mechanism.md) item 3), concatenates them into a digest and sends it to `POST /api/v1/memories` (via `internal/client`, the same client as the CLI/MCP) with `source=claude-code`, letting fact extraction (Phase 4/[D12](D12-llm-fact-extraction.md)) turn the digest into atomic facts — the hook itself extracts nothing, it only forwards redacted raw text. Registered as a hook with `"async": true` (Claude Code's native mechanism for not blocking the session while waiting for the embedding/LLM round-trip — no manual fork/detach needed in Go). Credentials (`M3M0S_URL`/`M3M0S_API_KEY`): read from the process environment or, if absent, from a dedicated local file (not embedded in the hook command in `~/.claude/settings.json`, so the key is not left in plain text in a global config file of deliberately broader purpose).

**Accepted risk, documented so it is not forgotten:** the transcript JSONL format is not a stable public API — Claude Code's official docs literally say that "the internal format is subject to change between versions" and recommend using the official export/script interfaces (Agent SDK, `getSessionMessages`) instead of reading the file directly. It was decided to use direct parsing in Go anyway (it avoids a Node/Python runtime dependency just for this, and keeps [D2](D2-stack-go-core-typescript-only-where-required.md) — "Go in the core" — without opening an exception), accepting that a Claude Code update may break the parser; if this proves fragile in practice, re-evaluate switching to the official Agent SDK (TypeScript or Python) as a thin adapter, the same exception pattern already used for `pi` ([D2](D2-stack-go-core-typescript-only-where-required.md)/`AGENTS.md` item 2).

**Out of scope for this decision:** auto-capture in `pi` (left for when Claude Code validates the concept), and any `PostToolUse`/`PreToolUse` hook (per-tool-call capture, not per end of session — rejected in the trigger, item 2 above, for LLM cost and noise).
