# D20 — Turn off `reasoning` on the extraction model (found in production minutes after D19 was running)

**Status:** Accepted

**Context:** the rebuild+redeploy of [D19](D19-forced-json-retry.md) went up at 00:37 (local time). A Claude Code `/compact` fired the `claude-code` hook right after, and the maintainer reported that it "did not work correctly" when looking at `docker logs m3m0s` and `~/.m3m0s/hooks/claude-code.log`. The logs showed 100% per-chunk failure since the container booted — **11 of 11** — all `context deadline exceeded`, and 3 POSTs from the hook to `/api/v1/memories` blowing the client's 30s timeout. In other words: no [D19](D19-forced-json-retry.md) symptom (empty response, loose prose) appeared — the pre-[D19](D19-forced-json-retry.md) pattern was back, pure timeout, now on practically every call, not just a fraction.

A direct test against OpenRouter's API, from inside the container itself, isolated the cause: a trivial, repetitive prompt (the same sentence repeated ~70 times, with no real facts to extract) took **8.5s** and spent **475 `reasoning` tokens** before answering with 1 obvious fact. `usage.completion_tokens_details.reasoning_tokens` confirmed: `DefaultModel` (`deepseek/deepseek-v4-flash`) is a reasoning model — "flash" does not mean a fast response, it means it "thinks" in a chain before answering, and that reasoning is billed as output tokens, subject to the same 20s timeout of the entire HTTP call. On real content (varied, not repetitive, with code/decisions — far richer than the test sentence), the chain of reasoning grows and blows the 20s almost guaranteed. This retroactively explains [D18](D18-chunked-fact-extraction.md) (timeouts) AND [D19](D19-forced-json-retry.md) (empty responses/loose prose — generation probably cut off in the middle of reasoning before emitting the final JSON): both were symptoms of the same root cause, never isolated until now.

Repeating the same test with `"reasoning": {"enabled": false}` in the payload: **1.43s**, **0 reasoning tokens**, correct and complete `{"facts": [...]}` JSON.

**Decision:** `internal/extract/extract.go` — a new field `Reasoning *reasoningConfig` in `chatRequest` (`{"reasoning": {"enabled": false}}`, a documented OpenRouter field), set in both `Extract` and `Classify` — neither task needs visible reasoning (the answer is always a short JSON or 1 word), only the final result. Unlike [D19](D19-forced-json-retry.md) (`response_format`, only in `Extract`), here the change applies to both calls because the bottleneck is the same (the model's generation latency), not the response format.

**Why this does not invalidate [D18](D18-chunked-fact-extraction.md)/[D19](D19-forced-json-retry.md):** [D18](D18-chunked-fact-extraction.md) (slicing) is still necessary — it reduces the size of each call, which by itself already reduces reasoning time even with reasoning on, and isolates per-chunk failure regardless of the cause. [D19](D19-forced-json-retry.md) (`response_format` + budgeted retry) remains useful as reinforcement for the cases where the provider behind OpenRouter ignores `reasoning.enabled=false` (not every provider/model necessarily honors the field) or fails for some reason other than reasoning. D20 attacks the most probable and cheapest-to-fix cause, it does not replace the two previous ones.

**Why not switch models now:** the same reasoning as [D19](D19-forced-json-retry.md) — deciding on a replacement and validating cost/quality is a bigger decision, outside the scope of this targeted fix. It is easier to reopen later if D20 is not enough, since there is now a direct test (outside the m3m0s process) to compare latency with/without reasoning per model.

**Out of scope for this decision:** making `reasoning.enabled` configurable via env var (the same minimalist spirit as [D12](D12-llm-fact-extraction.md)/[D14](D14-claude-code-hook-auto-capture.md)/[D18](D18-chunked-fact-extraction.md)/[D19](D19-forced-json-retry.md) — if a future model needs reasoning on, that becomes a new decision, not a preventive flag); lowering the fixed 20s timeout back (D20's gain is extra headroom under the current ceiling, not a reason to tighten it).
